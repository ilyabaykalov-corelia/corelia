# Corelia

Основа настраиваемого продукта для работы с документами и процессами. Java 25, Spring Boot 4.0.8, Maven. Пять приложений запускаются независимо; DataSpace, BPMN и DAM Platform V продолжают хранить данные и исполнять бизнес-правила.

Рабочий контур состоит из сервисов Corelia и библиотеки контракта Platform V. Пользовательский интерфейс подключается к универсальному API gateway.

## Git-репозитории

Corelia — корневой репозиторий с восемью Git submodules для сервисов, библиотек
и тестов. Он фиксирует совместный состав модулей и общие файлы проекта.
Порядок клонирования, коммитов и настройки удалённых адресов описан
в [инструкции по подмодулям](docs/git-submodules.md).

## Сервисы

| Приложение | Ответственность |
| --- | --- |
| `corelia-gateway` | Внешний универсальный API и сборка ответов сервисов для React-клиента |
| `corelia-auth` | Вход, обновление и завершение сессии через заменяемый провайдер; сейчас Keycloak |
| `corelia-document-service` | Карточки ПДС, проверка структуры атрибутов, отображение модели платформы |
| `corelia-workflow-service` | Запуск процессов, чтение задач, выполнение вариантов завершения из BPMN |
| `corelia-attachment-service` | Загрузка, скачивание и версии файлов; метаданные в DataSpace, содержимое в DAM |

`corelia-common` и `corelia-platform-v` — библиотеки, а не отдельные процессы. `corelia-system-tests` — проверки взаимодействия. Приложения не зависят от JAR других приложений: общаются через внутренний HTTP API.

Название gateway подходит для внешней точки входа. Он выполняет агрегацию ответов сервисов для клиента; Spring Cloud Gateway здесь не используется: приложение собрано на Spring MVC и Java HttpClient.

## Локальный запуск в Docker

Нужны работающий Docker с Compose, OpenSSL и `keytool` из JDK. Для сборки вне Docker — Java 25 и Maven 3.9+. На Mac с установленным Homebrew OpenJDK:

```bash
cd /Users/ilyabaykalov/Projects/aplana/sber-npf/corelia
export JAVA_HOME=/opt/homebrew/opt/openjdk/libexec/openjdk.jdk/Contents/Home
cp -n .env.example .env
# Заполните в .env адреса и идентификаторы вашего стенда, если они ещё не перенесены.
./scripts/up.sh
# Запуск без выполнения тестов при сборке образов:
./scripts/up.sh --skip-tests
```

Gateway доступен по `http://localhost:7170`. Другой порт: `CORELIA_GATEWAY_PORT=7171 ./scripts/up.sh`. Настройка адреса API клиента в таком случае выполняется отдельно.

```bash
curl --fail http://localhost:7170/api/core/v1/health
docker compose ps
docker compose logs --tail 100 corelia-gateway
./scripts/down.sh
```

Логи читаются из stdout контейнеров: `docker compose logs -f corelia-gateway corelia-document-service`.
Интеграционные события выводятся строкой `сообщение JSON`, а `X-Request-Id` позволяет связать
запрос gateway с вызовами внутренних сервисов. Уровень задаётся `CORELIA_LOG_LEVEL=INFO`.

Скрипт запуска генерирует сертификаты, собирает образы и ждёт готовности сервисов. На хост опубликован только gateway, только на loopback. Внутренние сервисы требуют mTLS даже для healthcheck. Их адреса и сертификаты уже связаны в Compose. Пустые параметры Platform V допускают запуск, но операции платформы вернут 503. Healthcheck подтверждает запуск приложения, а не доступность внешнего стенда.

`.env` и `.local` исключены из Git и контекста Docker-сборки. Закрытый ключ локального CA не передаётся контейнерам. Сертификаты действуют 90 дней. Это локальный стенд; порядок ротации и границы защищённого контура описаны в [эксплуатации](docs/operations.md).

## Настройка заказчика и новые документы

Каждый заказчик разворачивает отдельную систему в своём контуре. Адреса интеграций и параметры запуска задаются через переменные окружения; модель данных, права и BPMN настраиваются в Platform V.

API `/api/core/v1` возвращает карточку с `typeCode`, `attributes`, `status` и контекстом workflow. Клиент использует этот универсальный контракт; бизнес-логика остается в сервисах Corelia и Platform V.

Контракт ПДС описан в адаптере `corelia-platform-v`, точные разрешённые GraphQL-запросы находятся в его ресурсах `graphql/`. Добавление нового типа требует настройки модели, прав и процесса в платформе, а также реализации соответствующего контракта в сервисах. Нового микросервиса для каждого вида документа не требуется.

Подробности: [API](docs/api.md), [архитектура и решения](docs/architecture.md).

## Сборка и проверка

```bash
./scripts/test.sh
# Дополнительно: проверка собранных Docker-образов на тестовой платформе.
docker compose build
./scripts/test.sh -DdockerSmoke=true
```

Тесты запускают пять настоящих приложений с mTLS и имитацию DataSpace/BPMX/BPMU/DAM/Keycloak. Проверяются универсальные документы, вложения, задачи, JWT и права сервисов. Docker-проверка использует отдельный Compose-проект `corelia-smoke` и удаляет его контейнеры после выполнения. Рабочий стенд в проверках не используется.

Maven создаёт обычный JAR и исполняемый `*-exec.jar`. Например, отдельная сборка gateway: `mvn -pl corelia-gateway -am package -DskipTests`. Для локального запуска JAR потребуются те же адреса, mTLS-ключи и пароль, что в Compose; для первого запуска удобнее использовать готовый Docker-сценарий.

Фактические результаты текущей проверки: [verification.md](docs/verification.md).
