# Архитектура Corelia

Карта компонентов и последовательности операций находятся в [описании реализации](implementation.md).

## Границы ответственности

Corelia владеет прикладными правилами документов; DataSpace хранит данные и обеспечивает атомарные пакеты. Реализованные интерфейсы DocumentRepository и DocumentVersionRepository отделяют сценарии от хранения. В текущем коде контракт ПДС всё ещё расположен в библиотеке интеграции, а контракт KidOps — в common; полная независимость домена от платформы остаётся направлением развития.

Gateway на Spring MVC и Java HttpClient агрегирует ответы без самостоятельного выбора бизнес-переходов. Карточку и состав выбранного снимка возвращает document-service; gateway добавляет workflow. Для APPROVED, REJECTED и STORED он возвращает пустой workflow без поиска активной задачи.

Document-service вызывает workflow для создания и проверки исполнителя, а attachment-service — для подготовки обязательного первого файла КИД ОПС. Attachment-service вызывает document-service для проверки доступа и изменения состава. Workflow не зависит от document-service. Обратных вызовов в gateway нет.

Публичный documentId должен быть уникален между видами: Attachment ссылается на документ строковым ID без typeCode. Document, дочерние реквизиты, версии и результаты команд образуют модель хранения; бинарное содержимое находится отдельно в DAM. Собственной общей базы бизнес-сущностей у сервисов нет.

Существующие BPMN создают сущности и меняют status непосредственно в DataSpace. Новые правила изменения документов следует размещать в ядре; нельзя считать текущие BPMN только транспортом и игнорировать их при изменении модели.

## Транспорт и безопасность

Внутренние запросы используют JSON/HTTPS с mTLS, поддержкой HTTP/2 и допустимым HTTP/1.1 в том же TLS. Spring использует виртуальные потоки. Сравнительные нагрузочные преимущества над другими протоколами не подтверждены.

Сертификат определяет вызывающий сервис, JWT — пользователя. JWT RS256 проверяется по подписи, issuer, exp, nbf; ключи JWKS кэшируются и обновляются. Пользовательский токен передаётся платформе. Corelia не выпускает собственные access token; роли берутся из подписанного токена, без исключений по логину.

Фактические ограничения реализованы в [RequestSecurity.java](../corelia-common/src/main/java/ru/corelia/http/RequestSecurity.java):

| Получатель | Разрешённые вызовы |
| --- | --- |
| auth | Gateway |
| document-service | Gateway; attachment-service — GET и POST команд состава |
| workflow-service | Gateway; document-service — процессные пути и GET workflow документа |
| attachment-service | Gateway; document-service — POST подготовки первого файла |
| Внутренний health | Дополнительно собственный сертификат приложения |

attachment-commands доступны только attachment-service; initial-attachments — только document-service. CN проверяется после TLS-проверки сертификата доверенным CA. Допуск сертификата не заменяет JWT и прикладную авторизацию.

Вход сейчас использует Keycloak password grant. IdentityProvider позволяет заменить реализацию, но формат токенов нового провайдера должен быть согласован с JWT/JWKS и платформой. PKCE и поддержка opaque token не реализованы.

## Согласованность и развитие

Команды реквизитов и состава используют результаты в DocumentCommand, хеш запроса и проверку состояния в атомарном пакете. Создание КИД ОПС имеет отдельный механизм повторов; создание ПДС и запуск BPM не получают от этого общей гарантии идемпотентности. После таймаута запуска результат может быть неизвестен.

Нет общей транзакции между DAM, BPM и DataSpace. Проверка исполнителя также не атомарна со сменой статуса из BPMN. Границы восстановления описаны в [версионировании](document-versioning.md) и [КИД ОПС](kid-ops.md).

Каждое развёртывание обслуживает одного заказчика. Реализован провайдер platform-v; неизвестный провайдер отклоняется конфигурацией. Замена хранилища должна сохранять контракты ядра, уникальность идентификаторов, атомарность и контроль конкурентных изменений. Новые брокеры, собственное хранилище или перенос всех BPMN-правил не являются обязательной частью локального изменения.
