# Теоретическая оценка прежнего личного Corelia

Изучен проект `/Users/ilyabaykalov/Projects/personal projects/corelia`. Его код, зависимости и функции в новую реализацию не переносились. Оценка касается найденной реализации Java, а не обещаний README: README описывает более широкий замысел воркфлоу с агентами и не совпадает полностью с составом Java-модулей.

| Найденная часть | Полезная идея для продукта | Условия будущего использования |
| --- | --- | --- |
| `corelia-model-service`, `YamlDataTypeFacade`, YAML DTO/мапперы | Декларативное описание типов и атрибутов | Согласовать модель с DataSpace и жизненным циклом схем; не подключать JPA-модель параллельно текущему источнику данных |
| `corelia-ui-service`, FormController, JsonFormFacade, FormService | Формы как метаданные, отделённые от конкретного фронтенда | Определить стабильную UI-схему, версии компонентов и клиентский renderer; React сейчас не меняется |
| `corelia-artifact-watcher`, ArtifactWatcher, ArtifactPublisher, Avro-события | Доставка изменений конфигурационных артефактов | Нужны валидация всей версии конфигурации, атомарная публикация, идемпотентность, обработка повторов и откат |
| `MultiLanguageString`, Language и валидаторы | Локализованные подписи метаданных | Согласовать формат API, fallback-язык и миграцию конфигов |
| `corelia-webapp`, общая обработка ошибок и YAML parser | Единые технические соглашения | Отбирать маленькие независимые части; не переносить целиком связанный фреймворк |

В найденных Maven-файлах используются Java 21 и семейство Spring Boot 3.4.5, JPA/Hibernate и Kafka-компоненты. Новый проект использует Java 25 и Spring Boot 4.0.8, поэтому прямое подключение старого parent или JAR потребовало бы отдельной проверки совместимости библиотек и API.

Наиболее полезное направление — метаданные форм и локализация: они помогают менять фронтенд заказчика при стабильных сервисах. Следом можно изучать управляемые релизы конфигурационных артефактов. Старый model-service не следует объявлять готовой заменой DataSpace: сначала нужны контракты хранения, permissions, миграций, конкурентных изменений и эксплуатации. Аналогично наличие watcher/Kafka не доказывает готовность распределённой доставки конфигураций.

Текущий шаг ограничен границами сервисов и адаптерами действующей платформы. Отдельные ui-service, model-service, watcher и Kafka из прежнего проекта не добавлены.
