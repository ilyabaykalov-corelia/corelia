# Проверка Corelia

Команды выполняются из корня Corelia. Нужны Java 25, Maven 3.9+ и возможность слушать локальные TCP-порты; для Docker smoke — Docker Compose. Скрипт test.sh подготавливает сертификаты через init-local.sh и запускает Maven verify.

```bash
./scripts/test.sh
```

Для проверки собранных контейнеров:

```bash
docker compose build
./scripts/test.sh -DdockerSmoke=true
```

## Что проверяют тесты

| Источник | Область |
| --- | --- |
| CoreliaIntegrationTest | HTTP/mTLS взаимодействие приложений, авторизация, документы, задачи, версии, файлы и КИД ОПС |
| DocumentVersionServiceTest | Общий алгоритм снимков, повторов, конфликтов и файлового состава |
| KidOpsValidationTest | Валидация реквизитов КИД ОПС |
| DockerSmokeTest | Вызовы gateway собранного Docker-контура с тестовой платформой |
| PlatformStub и allowed-requests.json | Имитация внешних API и независимые разрешённые тексты GraphQL |

Файлы находятся в `corelia-system-tests/src/test`. Обычные тесты используют имитацию DataSpace/BPM/DAM/Keycloak. Docker smoke работает в отдельном проекте corelia-smoke. Эти проверки не изменяют данные рабочего стенда и не исполняют настоящий SDK-генератор, модель permissions или BPMN-движок.

При изменении GraphQL сверять ресурс адаптера, полное тело разрешённого запроса в платформе и независимую фикстуру. При изменении межсервисной команды проверять права вызывающего сертификата, успешный путь, конфликт и повтор после потерянного ответа.

## Смежные проверки

Из корня Corelia при наличии соседних репозиториев:

```bash
npm --prefix ../sber-npf-react run build
bash ../sber-npf-platform-v/scripts/package-platform-v.sh
```

Установка совместимого комплекта платформы требует проверки реального создания обоих видов, инициализации v1, редактирования без смены процесса, истории файлов, конфликтов и перехода КИД ОПС в STORED. Способ миграции имеющихся данных и процессов должен быть определён до установки; автоматического плана миграции старой модели эта документация не предоставляет.

## Как фиксировать результат

Указывать проверенный состав коммитов, команду, окружение, фактический результат и непроверенные внешние зависимости. Не переносить числа тестов из старого отчёта на новую версию. Health проверяет запуск приложения, а не доступность всех интеграций.

При обновлении документации 16 сентября 2026 года прикладная сборка, тесты и развёртывание не запускались. Проверка Markdown-ссылок и соответствия описаний исходникам не является проверкой работоспособности стенда.

## Проверки внешней конфигурации

`ConfigurationLoaderTest` проверяет неверные версии, keywords, ссылки, пути, дубли и реквизиты. `ConfigurationCompilerTest` проверяет сохранение тел и privileges существующего комплекта и воспроизводимый manifest. `ConfigurationContractTest` загружает два разных customer registry одними классами продукта, проверяет mapping, CAS-переменные, политику вложений, workflow process/external fields и поиск. Это не заменяет полный запуск двух независимых Platform V-развёртываний.

Полный прогон использует соседние sber-npf-corelia-config и sber-npf-platform-v для миграционного контракта. Docker smoke получает внешний пакет через read-only mount. Для чистой сборки после `scripts/init-local.sh` используйте `mvn -B -ntp clean verify`, а не `scripts/test.sh clean` (скрипт добавляет аргументы после verify).

Текущие результаты и незавершённые этапы фиксируются в `../task completion progress.md` общей рабочей папки.
